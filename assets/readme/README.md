# README screenshot plan

The root README contains four commented screenshot slots. Add the final captures with
the exact filenames below, then replace each corresponding comment with its Markdown
image line. Keeping the slots commented avoids broken images before the assets exist.

| File | README position | Required content |
|---|---|---|
| `library.png` | After “Interface preview” | Desktop Library view with at least one YouTube source and one X/Twitter source; show honest status badges |
| `reader.png` | After “Read without losing provenance” | A fixture-backed source unit, its source citation, and coverage state |
| `knowledge-map.png` | After “Explore connections” | A focused node, related knowledge, legend, and Quick Read at a readable zoom |
| `obsidian.png` | After “Use the result in Obsidian” | A disposable generated vault showing linked source and derived notes |

Capture rules:

- Use committed fixtures or other non-private demonstration data.
- Use the production build, not a design mockup.
- Crop browser chrome and unrelated desktop content.
- Keep text readable at GitHub's normal README width; prefer 1600×1000 or a similar
  16:10 desktop viewport and export PNG.
- Use one consistent theme and locale across the three Knowledge Canvas captures.
- Do not edit away `PARTIAL`, `FAIL`, missing values, or other honest states.
- Give each image meaningful alt text, as already drafted in the root README comments.
- Optimize files before committing them, without making labels or provenance unreadable.

The existing `x2knwldg-hero-dark-v3.png` remains the hero image and is not one of the
four product screenshots.
